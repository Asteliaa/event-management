# EventHub · ПЗ1 «Middleware и шаблонизаторы»

Практическое занятие № 1 по дисциплине «Интернет-технологии и веб-программирование. Часть 2».
Серверное приложение на Express.js с шаблонизатором EJS: каталог конференций, вебинаров и встреч.
Данные хранятся в PostgreSQL (таблица `events`, пакет `pg`).

## Требования

- Node.js 18 или новее (проверено на Node.js 22)
- npm
- PostgreSQL 13 или новее (проверено на PostgreSQL 16)

## Запуск

1. Скопируйте `.env.example` в `.env` и укажите пользователя и пароль PostgreSQL:

   ```
   DATABASE_URL=postgres://postgres:ПАРОЛЬ@localhost:5432/eventhub_pz1
   TEST_DATABASE_URL=postgres://postgres:ПАРОЛЬ@localhost:5432/eventhub_pz1_test
   ```

2. Установите зависимости, создайте базы и запустите сервер:

   ```bash
   npm install
   npm run db:create  # создает eventhub_pz1 и eventhub_pz1_test, если их нет
   npm start          # http://localhost:3000
   ```

Таблица `events` и начальные мероприятия создаются автоматически при первом запросе.

Режим разработки с автоперезапуском:

```bash
npm run dev
```

Другой порт: `PORT=3001 npm start` (PowerShell: `$env:PORT=3001; npm start`).

Автотесты (189 проверок: страницы, некорректный ввод, поломки журнала, сбои базы данных).
Тесты работают только с базой `TEST_DATABASE_URL`, рабочая база не затрагивается:

```bash
npm test
```

## Маршруты

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/` | Список мероприятий; параметры `q` (поиск) и `type` (`conference`, `webinar`, `meetup`) |
| GET | `/item/:id` | Детальная страница мероприятия |
| GET | `/add` | Форма добавления (только организатор) |
| POST | `/add` | Проверка и добавление в базу данных, редирект на главную |
| GET | `/login` | Страница входа (имитация) |
| GET | `/logs` | Журнал запросов из файла `logs/requests.log` (только организатор) |
| любой | другой адрес | Страница 404 |

## Имитация авторизации

Режим организатора включается параметром `?auth=1` в адресе, например
<http://localhost:3000/?auth=1>. Ссылки внутри сайта сохраняют этот параметр.
Без него пользователь – «Гость»: может смотреть список и карточки, а при переходе на `/add`
перенаправляется на `/login`.

## Middleware

| Файл | Назначение |
|---|---|
| `middleware/logger.js` | Логирование: время, метод и URL – в файл `logs/requests.log`; код ответа и длительность – в консоль |
| `middleware/auth.js` | `simulateAuth` (Гость / Организатор по `?auth=1`), `requireAuth` (редирект на `/login`) |
| `middleware/errors.js` | 404, 405, общий обработчик ошибок `(err, req, res, next)` со страницей 500 и понятным сообщением |
| `middleware/securityHeaders.js` | Общие заголовки ответа (`X-Powered-By`, `X-Content-Type-Options`, CSP) |

Порядок подключения: заголовки → статика → `simulateAuth` → логирование → маршруты → 404 → обработчик ошибок.
Авторизация стоит раньше журнала, поэтому на странице 500 из-за сломанного журнала в шапке остается «Организатор».

```

```

## База данных и ошибка 500

- PostgreSQL остановлен или недоступен – страницы с данными отвечают 500 с сообщением
  «Нет соединения с базой данных: сервер PostgreSQL остановлен или недоступен».
  Страницы без данных (вход, форма, 404) продолжают работать.
  После запуска PostgreSQL сайт снова работает без перезапуска сервера.
- Неверное имя базы, пароль или адрес сервера – 500 с понятным описанием причины.
- Таблицу `events` удалили во время работы – при следующем запросе она создается заново.
- Системный текст ошибки (`ECONNREFUSED`, код PostgreSQL) выводится только в консоль сервера.

## Журнал запросов и ошибка 500

Каждый запрос записывается в `logs/requests.log` (время, метод, URL).

- Файл удален или переименован – при следующем запросе создается новый.
- Папка `logs` удалена – создается заново.
- Журнал восстановить нельзя (вместо файла `requests.log` создана папка, вместо папки `logs` – файл,
  нет прав на запись или чтение) – сайт показывает страницу 500 с понятным сообщением,
  например «по пути logs/requests.log находится папка, а не файл журнала».
  Системный текст ошибки выводится только в консоль сервера.
  Когда причину устранили, сайт снова работает без перезапуска.

Папку журнала можно изменить переменной окружения `LOG_DIR`.

## Проверка ввода

- Пустые поля и поля из одних пробелов (в том числе неразрывных и невидимых) не принимаются.
- Длина каждого поля ограничена в форме (`maxlength`) и повторно на сервере:
  название – 120, место – 150, организатор – 80, описание – 1000, количество мест – 5 символов.
- Количество мест – целое число от 1 до 10 000, дата и время – корректного формата,
  тип и формат – только из списка.
- Мероприятие нельзя добавить в прошлом: дата не раньше сегодняшней,
  а для сегодняшней даты время начала еще не наступило.
- Ограничения длины продублированы в таблице (`VARCHAR`, `CHECK`), запросы параметризованы.
- Запрос больше 20 КБ или с лишними полями отклоняется (413).
- Вывод экранируется (`<%= %>`), поэтому HTML и скрипты в полях показываются как текст.
